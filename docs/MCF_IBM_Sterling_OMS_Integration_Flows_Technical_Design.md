# IBM Sterling OMS – Amazon MCF Integration Flows

## Technical Design Document

---

## 1. Solution Overview

This integration connects **IBM Sterling Order Management System (OMS)** with **Amazon Multi-Channel Fulfillment (MCF)** via the **Selling Partner API (SP-API)**. It runs as a set of Sterling extension classes (processors and agents) inside the OMS runtime and reuses the OMS-side plumbing (services, agents, common utilities) shared with the Buy with Prime base package.

Inbound MCF updates (shipment, package milestone, cancel) can be handled by a **reconciliation agent** — a polling-based approach for merchants who do not integrate via Amazon's event notifications (which require AWS SQS). It pulls an order snapshot from Amazon, applies the differences against OMS state, and can additionally surface package delivery milestones that notifications do not provide; see §3 for details.

**orderId mapping.** The `orderId` sent to Amazon at create time is `<OrderNo>-<zero-padded ReleaseNo>` (e.g., `Y100001234-01`). On success the Amazon order id and per-line alias are stamped back onto the OMS order line as `ExtnAmazonOrderId` and `ExtnAmazonLineItemAlias`.

**Idempotency.** Every reconciliation action is guarded by an OMS-state check, so re-running the agent over the same Amazon snapshot is safe:
- **Shipment** — skipped if a container already exists for the `amazonShipmentId` (`getShipmentContainerList` returns > 0 records).
- **Milestone** — skipped per tracking number + status if the status already exists in `AMZ_CONN_CONTAINER_MILESTONES`.
- **Cancel** — cancels only the **delta** between Amazon's cancelled/unfulfillable quantity and what OMS has already cancelled (`OrderStatus` ≥ 9000).

**Key field mappings (Amazon → OMS):**

| Amazon | OMS |
|--------|-----|
| `orderId` | `ExtnAmazonOrderId` / `AmazonOrderId` |
| `lineItemId` | `ExtnAmazonLineItemAlias` (= `OrderLineKey`) |
| `amazonShipmentId` | `ExtnAmazonDeliveryId` (container lookup) |
| `packages/tracking/carrier/@trackingNumber` | `TrackingNo` / `CarrierCode` on Container |
| `merchantId` | resolved to `EnterpriseCode` |

**API version note.** The outbound create and inbound snapshot list use SP-API Fulfillment Outbound **`2026-07-04`** (live). The shipment / milestone / cancel snapshots are **internally reconstructed representations** generated by the reconciliation agent (see §3), not a live notification version.

## 2. Flow 1: Create Fulfillment Order in Amazon

**Purpose:** When an order is released in Sterling, transform the released MCF-eligible lines into an SP-API `createFulfillmentOrder` request, call Amazon, and stamp the Amazon order id back onto the OMS order lines.

**Trigger:** Release-order ON_SUCCESS message (`AmzProcessReleaseOrderMessageWithMCF.processReleaseOrderMessage`).

### Sequence Diagram

```
┌──────────┐        ┌─────────┐        ┌─────────┐        ┌────────┐
│ Release  │        │   OMS   │        │ Sterling│        │ Amazon │
│ ON_SUCCESS│       │ (this   │        │  APIs   │        │ SP-API │
│ message  │        │ code)   │        │         │        │        │
└────┬─────┘        └────┬────┘        └────┬────┘        └───┬────┘
     │  message           │                  │                 │
     │───────────────────>│                  │                 │
     │                    │ verifyMCFCreateOrdEligibleLines     │
     │                    │ (Status=3200, ShipNode,             │
     │                    │  Fulfillable=Y, PrimeElig=N,        │
     │                    │  no ExtnAmazonOrderId)              │
     │                    │                  │                 │
     │                    │ prepareMCFCreateFulfillmentOrderJSON│
     │                    │ (getReleaseNo for orderId,          │
     │                    │  ship-to address, lineItems)        │
     │                    │─────────────────>│                 │
     │                    │  release detail  │                 │
     │                    │<─────────────────│                 │
     │                    │                  │                 │
     │                    │ getSPAuthorizationToken             │
     │                    │  POST /fulfillment/outbound/        │
     │                    │       2026-07-04/orders             │
     │                    │────────────────────────────────────>│
     │                    │  {} (success) / {errors:[...]}      │
     │                    │<────────────────────────────────────│
     │                    │                  │                 │
     │                    │ [success] changeOrder:              │
     │                    │  stamp ExtnAmazonOrderId +          │
     │                    │  ExtnAmazonLineItemAlias            │
     │                    │─────────────────>│                 │
     │                    │ [+ updateOMSOrderRelease]           │
     │                    │                  │                 │
     │                    │ [insufficient qty] changeRelease→   │
     │                    │  backorder/cancel release line      │
     │                    │ [other error] createNewException (alert)
     │                    │                  │                 │
```

### OMS API / Method Calls

| Step | Class / API | Purpose |
|------|-------------|---------|
| 1 | `AmzProcessReleaseOrderMessageWithMCF.verifyMCFCreateOrdEligibleLines` | Select MCF-eligible released lines (Status `3200`, matching ShipNode, `ExtnIsAmazonFulfillable=Y`, `ExtnIsPrimeEligible=N`, no `ExtnAmazonOrderId`) |
| 2 | `MCFPrepareSPAPICreateFulfillmentOrderRequest.prepareMCFCreateFulfillmentOrderJSON` | Build SP-API JSON (`orderId`, `displayableOrderId`, `fulfillmentConfiguration`, `destination.deliveryAddress`, `lineItems`) |
| 3 | SP-API `POST /fulfillment/outbound/2026-07-04/orders` | Create the fulfillment order in Amazon |
| 4 | `changeOrder` service | On success, stamp `ExtnAmazonOrderId` + `ExtnAmazonLineItemAlias` on the OMS lines |
| 5 | `AmzUpdateOrderRelease.updateOMSOrderRelease` | Update the release with the Amazon order id (released-order path) |

### Key Logic
- `orderId` = `<OrderNo>-<zero-padded ReleaseNo>`; `displayableOrderId` = bare `OrderNo`.
- `lineItemId` = `OrderLineKey`; `amazonSku` = `ItemID`; `amount.unit` = `EACHES`.
- Success response is empty `{}` (or has no `errors` key). No Amazon callback is needed — the ids are already known from the request body.
- Error handling: `insufficient quantity unavailable` → backorder or cancel the release line (`BACKORDER` if the generic property `amzConn.MCF.BackOrderCancelledLine=Y`, otherwise `CANCEL`), then raise an exception alert; any other error → raise an exception alert.

## 3. Flow 2: MCF Order Reconciliation Agent (inbound)

**Purpose:** The reconciliation agent is a **polling-based inbound approach** that merchants can use when they do **not** plan to integrate via Amazon's event notifications — which currently require an **AWS SQS** setup to receive. Instead of consuming notifications, this agent periodically pulls an order snapshot from Amazon (`ListMCFOrders`), diffs it against current OMS state, and — only for the deltas that still need action — generates **internal, event-shaped snapshots** (shipment / package-milestone / cancel) and invokes the corresponding processor classes **in-process**. Those processors are internal handlers called directly by the reconciler; they are not driven by an external event or notification feed.

This approach also gives the connector richer delivery visibility — it can pull package delivery milestones (in-transit, delivered, and other package status updates) directly from the order snapshot, complementing the shipment and cancellation coverage available through event notifications.

The connector's event processors are designed to be driven either in-process by the reconciliation agent (the current inbound approach) or by a notification-based path; receiver classes for the latter are present in the codebase, so the same processing logic supports future adoption of MCF notifications with minimal rework.

**Trigger:** Scheduled OMS agent (`AmzMCFOrderReconciliationAgent`, extends `YCPBaseAgent`). `getJobs` calls `ListMCFOrders` with an `updatedAfter` timestamp (default: now − 2h) and returns one job per `orders` element; `executeJob` hands each snapshot to `AmzReconcileMCFOrderSnapshot.reconcile`.

### Sequence Diagram

```
┌─────────┐      ┌──────────────┐      ┌─────────┐      ┌────────┐
│  Timer  │      │  Recon Agent │      │   OMS   │      │ Amazon │
│         │      │  + Reconciler│      │  APIs   │      │ SP-API │
└────┬────┘      └──────┬───────┘      └────┬────┘      └───┬────┘
     │ trigger          │                    │                │
     │─────────────────>│                    │                │
     │        getJobs:  │  ListMCFOrders (updatedAfter)        │
     │                  │─────────────────────────────────────>│
     │                  │  snapshot: orders[...]               │
     │                  │<─────────────────────────────────────│
     │                  │                    │                │
     │   ┌── executeJob: per order snapshot ─┐                │
     │   │              │ getOrderLineList    │                │
     │   │              │ (by lineItemId)     │                │
     │   │              │───────────────────>│                │
     │   │              │  OMS order/lines    │                │
     │   │              │<───────────────────│                │
     │   │              │                    │                │
     │   │   1. SHIPMENT branch (per shipment)                │
     │   │              │ getShipmentContainerList             │
     │   │              │───────────────────>│                │
     │   │              │ [records==0] build INTERNAL          │
     │   │              │  shipment snapshot → invoke          │
     │   │              │  AmzProcessMCFShipmentEvent          │
     │   │              │  → confirmShipment (create container)│
     │   │              │───────────────────>│                │
     │   │              │ [records>0] skip    │                │
     │   │              │                    │                │
     │   │   2. MILESTONE branch (per package)                │
     │   │              │ getAmzConnContainerMilestonesList    │
     │   │              │───────────────────>│                │
     │   │              │ [status missing] build INTERNAL      │
     │   │              │  package snapshot → invoke           │
     │   │              │  AmzProcessMCFPackageStatusEvent     │
     │   │              │  → insert milestone row              │
     │   │              │───────────────────>│                │
     │   │              │ [status exists] skip│                │
     │   │              │                    │                │
     │   │   3. CANCEL branch (per line item)                 │
     │   │              │ getOrderLineList / OrderStatus≥9000  │
     │   │              │───────────────────>│                │
     │   │              │ [delta>0] build INTERNAL cancel      │
     │   │              │  snapshot → invoke                   │
     │   │              │  AmzProcessMCFOrderStatusChangeEvent │
     │   │              │  → changeOrder / changeRelease       │
     │   │              │───────────────────>│                │
     │   │              │ [delta<=0] skip     │                │
     │   └────────────────────────────────────┘                │
```

### Reconciliation Diff / Decision Flow

The reconciler treats the Amazon snapshot as a **full picture, not a delta**, and queries OMS to decide what is still needed. It generates the three internal snapshots **only** for actions not already reflected in OMS, and always in the order **shipment → milestone → cancel** (a container must exist before milestones can be written, and cancellation must account for what was just shipped).

```
                 Amazon GetFulfillmentOrder snapshot (per order)
                                │
                                ▼
                    ┌───────────────────────┐
                    │ getOrderLineList       │  (resolve OMS order,
                    │ (by first lineItemId)  │   shipNode, enterprise)
                    └───────────┬───────────┘
                                │ found?
                     no ────────┴──────── yes
                     │                     │
                   SKIP                    ▼
                       ┌───────────────────────────────────┐
                       │ 1. SHIPMENTS                        │
                       │   container exists for              │
                       │   amazonShipmentId?                 │
                       │     yes → skip                      │
                       │     no  → INTERNAL shipment snapshot│
                       │           → AmzProcessMCFShipmentEvent
                       └───────────────────┬─────────────────┘
                                           ▼
                       ┌───────────────────────────────────┐
                       │ 2. PACKAGE MILESTONES               │
                       │   (per tracking#) status already   │
                       │   in AMZ_CONN_CONTAINER_MILESTONES? │
                       │     yes → skip                      │
                       │     no  → INTERNAL package snapshot │
                       │           → AmzProcessMCFPackageStatusEvent
                       └───────────────────┬─────────────────┘
                                           ▼
                       ┌───────────────────────────────────┐
                       │ 3. CANCELLATIONS                    │
                       │   amazonCancelled+unfulfillable     │
                       │   − omsCancelled(Status≥9000) = Δ   │
                       │     Δ <= 0 → skip                   │
                       │     Δ > 0  → INTERNAL cancel snapshot│
                       │           → AmzProcessMCFOrderStatusChangeEvent
                       └─────────────────────────────────────┘
```

### OMS API / Method Calls

| Step | Class / API | Purpose |
|------|-------------|---------|
| 1 | `AmzMCFOrderReconciliationAgent.getJobs` → `ListMCFOrders` | Pull orders updated since `updatedAfter`; one job per `orders` element |
| 2 | `AmzReconcileMCFOrderSnapshot.reconcile` | Resolve OMS order (`getOrderLineList`), shipNode, enterprise; drive the three branches |
| 3 | `AmzMCFSnapshotPayloadBuilder.buildShipmentEventPayload` | Build the internal `SHIPMENT_STATUS_CHANGED` snapshot |
| 4 | `AmzMCFSnapshotPayloadBuilder.buildPackageStatusPayload` | Build the internal `SHIPMENT_PACKAGE_STATUS_CHANGED` snapshot |
| 5 | `AmzMCFSnapshotPayloadBuilder.buildOrderStatusChangePayload` | Build the internal `ORDER_STATUS_CHANGED` snapshot (delta quantities) |

### Key Logic
- The three payload builders are **pure XML transformations** (static, no state, no API calls); the reconciler invokes the processors directly (`new AmzProcess…().process…(env, payload)`), so there is no queue hop.
- `getJobs` returns an empty list when `lastMessageCreated` is set (single pass per scheduled run).
- Orders missing in OMS (`getOrderLineList` empty / `MCF_RECONCILE_ERR_OL_LIST_EMPTY`) are skipped, not retried.

## 4. Reconciliation Action 2a: Shipment (internal)

**Purpose:** Create the OMS shipment container for a shipped Amazon shipment. Invoked **in-process** by the reconciliation agent (not from a queue).

**Entry point:** `AmzProcessMCFShipmentEvent.processShipmentEvent(env, internalShipmentSnapshot)`

### Sequence Diagram

```
┌──────────────┐        ┌─────────┐        ┌─────────┐
│ Reconciler   │        │   OMS   │        │ Sterling│
│ (in-process) │        │  code   │        │  APIs   │
└──────┬───────┘        └────┬────┘        └────┬────┘
       │ shipment snapshot   │                  │
       │────────────────────>│                  │
       │                     │ getShipmentContainerList (by
       │                     │  ExtnAmazonDeliveryId)          │
       │                     │─────────────────>│
       │                     │  records          │
       │                     │<─────────────────│
       │                     │ [0] getOrderLineList (by
       │                     │  ExtnAmazonLineItemAlias)       │
       │                     │─────────────────>│
       │                     │ build confirmShipment (container│
       │                     │  + tracking + shipment lines)   │
       │                     │  confirmShipment  │
       │                     │─────────────────>│
       │                     │ [>0] ignore (already exists)     │
```

### OMS API / Method Calls

| Step | API | Purpose |
|------|-----|---------|
| 1 | `getShipmentContainerList` | Dedup by `amazonShipmentId` (`ExtnAmazonDeliveryId`) |
| 2 | `getOrderLineList` | Resolve OMS order lines by `ExtnAmazonLineItemAlias` |
| 3 | `confirmShipment` | Create the container; tracking (`carrierCode` / `trackingNumber`) comes from the snapshot package |

### Key Logic
- Container missing → confirm shipment (create). Container present → ignore and log.
- Rejects the shipment if the order has multiple releases on the same ship node.

## 5. Reconciliation Action 2b: Package Milestone (internal)

**Purpose:** Record each package status (SHIPPED, IN_TRANSIT, DELIVERED, DELAYED, UNDELIVERABLE, RETURNED) as a row in the `AMZ_CONN_CONTAINER_MILESTONES` custom table. Invoked **in-process** by the reconciliation agent.

**Entry point:** `AmzProcessMCFPackageStatusEvent.processPackageStatusEvent(env, internalPackageSnapshot)`

### Sequence Diagram

```
┌──────────────┐        ┌─────────┐        ┌───────────────────────┐
│ Reconciler   │        │   OMS   │        │ AMZ_CONN_CONTAINER_    │
│ (in-process) │        │  code   │        │ MILESTONES (table)     │
└──────┬───────┘        └────┬────┘        └───────────┬───────────┘
       │ package snapshot    │                          │
       │────────────────────>│                          │
       │                     │ getShipmentContainerList  │
       │                     │ (by ExtnAmazonDeliveryId) │
       │                     │  [missing → create        │
       │                     │   container via shipment] │
       │                     │                          │
       │   ┌── per package (by tracking#) ──┐            │
       │   │                 │ read existing statuses    │
       │   │                 │──────────────────────────>│
       │   │                 │ [status exists] skip      │
       │   │                 │ [missing] insert milestone │
       │   │                 │──────────────────────────>│
       │   └─────────────────────────────────┘            │
```

### OMS API / Method Calls

| Step | Service / API | Purpose |
|------|---------------|---------|
| 1 | `getShipmentContainerList` | Locate the container (auto-creates via shipment if missing) |
| 2 | `getAmzConnContainerMilestonesList` | Per tracking number, load existing statuses for dedup |
| 3 | `amzConnUpdateMilestonesRecordInOMS` (service) | Insert the new package-status milestone row |

### Key Logic
- Per-package dedup is by **tracking number + status**; existing statuses are skipped.
- Packages with an empty status or tracking number are skipped.

## 6. Reconciliation Action 2c: Cancel / Unfulfillable (internal)

**Purpose:** Apply cancelled / unfulfillable quantities to the OMS order. Invoked **in-process** by the reconciliation agent with **delta** quantities (not full amounts).

**Entry point:** `AmzProcessMCFOrderStatusChangeEvent.processOrderStatusChangeEvent(env, internalCancelSnapshot)`

### Sequence Diagram

```
┌──────────────┐        ┌─────────┐        ┌─────────┐
│ Reconciler   │        │   OMS   │        │ Sterling│
│ (in-process) │        │  code   │        │  APIs   │
└──────┬───────┘        └────┬────┘        └────┬────┘
       │ cancel snapshot     │                  │
       │  (delta qtys)       │                  │
       │────────────────────>│                  │
       │                     │ getOrderLineList (by
       │                     │  ExtnAmazonLineItemAlias)       │
       │                     │─────────────────>│
       │                     │ per line:         │
       │                     │  MaxLineStatus==3200?           │
       │                     │   yes → changeRelease (cancel)  │
       │                     │   no  → changeOrder (cancel/    │
       │                     │          reduce qty + notes)    │
       │                     │─────────────────>│
```

### OMS API / Method Calls

| Step | Service / API | Purpose |
|------|---------------|---------|
| 1 | `getOrderLineList` | Resolve OMS line by `ExtnAmazonLineItemAlias`; validate single release per ship node |
| 2 | `changeRelease` | Cancel released quantity when the line is in Released status (`3200`) |
| 3 | `changeOrder` | Cancel (full) or reduce (`OrderedQty`, partial) with cancellation notes |

### Key Logic
- Cancel quantity per line = `cancelledAmount` + `unfulfillableAmount` (delta already computed by the reconciler).
- Full cancel (`remainingQty <= 0`) → `Action=CANCEL`; partial → reduce `OrderedQty`. Cancellation notes record the Amazon `orderId`, status, PrimeLine, and ItemID.

| Step | Class / API | Purpose |

## 8. Error Handling Pattern

- Processor classes throw `YFSException` with a coded `ErrorCode` (e.g., `MCF_RECONCILE_ERR_*`, `MCF_ORDER_STATUS_ERR_*`, `MCF_CREATE_FULFILLMENT_ORDER_FAILED`) and a description; requests/responses are logged via `AmzCommonUtil.logAmzConnRequest` / `logAmzConnResponse`.
- The reconciliation agent skips “order/line not found in OMS” (`MCF_RECONCILE_ERR_OL_LIST_EMPTY`) without retry; other failures are re-thrown so the agent can retry.
- Create-order errors branch on the Amazon message: `insufficient quantity unavailable` → backorder or cancel the release per the `amzConn.MCF.BackOrderCancelledLine` property (`BACKORDER` if `Y`, default `CANCEL`), followed by an exception alert; otherwise → exception alert.
